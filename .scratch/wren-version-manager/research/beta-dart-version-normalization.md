# Beta Dart version normalization

Checked 2026-10-27 against first-party Flutter and Dart sources. This note answers [Beta Dart version normalization](../issues/10-beta-dart-version-normalization.md).

## Catalog display versus runtime version

The [Flutter Linux release catalog](https://storage.googleapis.com/flutter_infra_release/releases/releases_linux.json) lists beta Flutter `3.50.0-0.2.pre` with `dart_sdk_version: "3.14.0 (build 3.14.0-315.3.beta)"`; its stable Flutter `3.47.8` entry lists plain Dart `3.13.7`. Flutter's [archive publisher](https://github.com/flutter/flutter/blob/7ebd8154adffd9a6f238dd19354849e7b20d67cb/dev/bots/prepare_package/archive_publisher.dart) copies `dartSdkVersion` from Flutter's machine version output into that catalog field. The [machine version output](https://github.com/flutter/flutter/blob/7ebd8154adffd9a6f238dd19354849e7b20d67cb/packages/flutter_tools/lib/src/version.dart) uses `globals.cache.dartSdkVersion`. That [cache getter](https://github.com/flutter/flutter/blob/7ebd8154adffd9a6f238dd19354849e7b20d67cb/packages/flutter_tools/lib/src/cache.dart) takes the first token of `Platform.version` and formats a prerelease as `<base> (build <full prerelease>)`. Thus `3.14.0` is a friendly display base, while `3.14.0-315.3.beta` is the runtime's version token.

The Dart CLI's [`--version` handler](https://github.com/dart-lang/sdk/blob/360290fc073606e120f3435322c74b593987cf60/runtime/bin/common_options.h) prints `Dart_VersionString()`, whose [version template](https://github.com/dart-lang/sdk/blob/360290fc073606e120f3435322c74b593987cf60/runtime/vm/version_in.cc) starts with the raw `VERSION_STR` followed by channel, build time, and host information. The [Dart team's advisory](https://github.com/dart-lang/sdk/security/advisories/GHSA-frr6-h895-5pxp) independently names Dart beta `3.14.0-315.3.beta` as the release paired with Flutter beta `3.50.0-0.2.pre`. **Inference from those sources:** the bundled beta executable's `dart --version` first version token is `3.14.0-315.3.beta`; this research did not download and execute the binary.

## Pub's constraint version

Pub's [`DartSdk.version`](https://github.com/dart-lang/pub/blob/1df594373b77e68ca4edee7211ef2105ae6908c4/lib/src/sdk/dart.dart) parses `Platform.version.split(' ').first` as a `pub_semver.Version`. Its [solver](https://github.com/dart-lang/pub/blob/1df594373b77e68ca4edee7211ef2105ae6908c4/lib/src/solver/package_lister.dart) checks the pubspec SDK constraint with `constraint.effectiveConstraint.allows(sdk.version)`. Consequently pub compares `3.14.0-315.3.beta`, not the catalog's display base `3.14.0`, for this beta. A prerelease sorts below its stable version under [pub's SemVer rules](https://github.com/dart-lang/tools/blob/eee87b12f5a7f42149c4dff130eb6d5600fae883/pkgs/pub_semver/README.md), so `^3.14.0` would exclude that beta.

## Rule for Wren

For catalog entries of the form `<base> (build <prerelease SemVer>)`, Wren should use the **full build SemVer** as its canonical bundled Dart version. For the example, it should compare project `environment.sdk` against `3.14.0-315.3.beta`, write `sdk: ^3.14.0-315.3.beta` when [Set command and pubspec update](../issues/02-set-and-pubspec.md) calls for rewriting an existing SDK key, and validate the installed Dart executable against the same full version token before publishing the install. Stable entries containing a plain SemVer use that value directly. This follows from Flutter's [display formatter](https://github.com/flutter/flutter/blob/7ebd8154adffd9a6f238dd19354849e7b20d67cb/packages/flutter_tools/lib/src/cache.dart), pub's [SDK version parser](https://github.com/dart-lang/pub/blob/1df594373b77e68ca4edee7211ef2105ae6908c4/lib/src/sdk/dart.dart), and the [official catalog](https://storage.googleapis.com/flutter_infra_release/releases/releases_linux.json).

The cited Flutter formatter and pub parser contain no host-specific branch for this version conversion, so the rule is the same for beta Dart on supported hosts. Wren should still validate each installed host executable. Flutter's [formatter](https://github.com/flutter/flutter/blob/7ebd8154adffd9a6f238dd19354849e7b20d67cb/packages/flutter_tools/lib/src/cache.dart) also replaces a historical `.flutter-<hash>` suffix with a space in its friendly display; those strings are not necessarily a single SemVer inside `build (...)`. Do not silently use the display base for such entries. The macOS catalog was not inspected directly in this research.

## Separate compatibility question

The [Dart pubspec documentation](https://dart.dev/tools/pub/pubspec) says caret syntax in SDK constraints was disallowed before Dart 2.19. The [Flutter catalog](https://storage.googleapis.com/flutter_infra_release/releases/releases_linux.json) includes beta releases bundled with Dart 2.18 and earlier. The Wayfinder decision to always write a caret SDK constraint therefore needs a separate historical-release policy; this fact does not change which Dart version pub compares for a beta.
