# Optional artifact repair inventory

Research for [Optional artifact repair inventory](../issues/14-optional-artifact-repair-inventory.md), 2026-10-28. I inspected first-party Flutter 3.7.0 (the oldest stable family at Wren's Dart 2.19 floor) and Flutter 3.47.0 (a recent stable release), with a small Linux filesystem reproduction of the cache freshness predicate. No complete Flutter SDK or macOS host was available locally, so the reproduction is source-level, not an end-to-end Flutter run. These samples expose a common gap; they do not certify every intermediate release.

## Result

**Flutter's cache cannot by itself implement the stated full `repair` promise.** Its group stamps and directory checks can find some candidate optional groups, but they do not validate the contents. A direct editor can fetch an optional group while Wren is absent; at the first Wren repair afterward there is no Wren-recorded digest manifest. Flutter removes its downloaded ZIP after extraction, and its engine metadata does not contain a per-file digest list. To validate that already-present group fully, Wren must obtain a trusted expected manifest, normally by fetching the group's archive or a separately maintained manifest, even if the group is healthy. That conflicts with the specification's “repair reports healthy without downloading if sound” promise for this case. [3.7.0 cache freshness and update](https://github.com/flutter/flutter/blob/3.7.0/packages/flutter_tools/lib/src/cache.dart#L774-L823), [3.47.0 cache freshness and update](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/cache.dart#L930-L975), [3.47.0 archive cleanup](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/cache.dart#L1452-L1476), [3.47.0 engine metadata schema](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/version.dart#L1373-L1414).

### Inventory evidence

- `CachedArtifact.isUpToDate` checks only that a location exists, the version matches its `<group>.stamp`, then delegates to a group hook. For engine groups that hook checks the expected **directories** and a few `LICENSE` files; it does not enumerate or hash archive entries. Some iOS USB groups check selected executable names, still only for existence. [3.7.0 general and engine checks](https://github.com/flutter/flutter/blob/3.7.0/packages/flutter_tools/lib/src/cache.dart#L774-L933), [3.7.0 iOS USB check](https://github.com/flutter/flutter/blob/3.7.0/packages/flutter_tools/lib/src/flutter_cache.dart#L766-L814), [3.47.0 general and engine checks](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/cache.dart#L930-L1039).
- **A directory is not a group marker.** On Linux x86_64, the universal `FlutterSdk` host archive and optional Linux desktop debug archive both extract into `bin/cache/artifacts/engine/linux-x64`; `font-subset` also uses that destination. A directory can exist before Linux desktop artifacts are fetched. Both sampled releases have this overlap, although the Linux debug ZIP URL changed. On macOS arm64, the universal host archive and optional macOS desktop ZIPs likewise share `engine/darwin-x64`. [3.7.0 Flutter SDK and Linux groups](https://github.com/flutter/flutter/blob/3.7.0/packages/flutter_tools/lib/src/flutter_cache.dart#L227-L348), [3.7.0 font subset](https://github.com/flutter/flutter/blob/3.7.0/packages/flutter_tools/lib/src/flutter_cache.dart#L731-L760), [3.7.0 macOS ZIP destinations](https://github.com/flutter/flutter/blob/3.7.0/packages/flutter_tools/lib/src/flutter_cache.dart#L854-L865), [3.47.0 Flutter SDK and Linux groups](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/flutter_cache.dart#L253-L370), [3.47.0 macOS ZIP destinations](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/flutter_cache.dart#L885-L900).
- Stamps are useful hints but not durable inventory. `precache --force` calls `clearStampFiles()`, which deletes **every** registered artifact stamp, before it chooses the artifact flags for this invocation; a targeted force run can erase evidence for other, previously fetched groups. A missing or corrupt stamp therefore cannot mean “never used.” If both a group's unique files and its stamp have gone, the current tree can match a tree in which that group was never fetched. Whether a fully erased group counts as “already present” needs an explicit boundary. [3.7.0 force and selection](https://github.com/flutter/flutter/blob/3.7.0/packages/flutter_tools/lib/src/commands/precache.dart#L132-L166), [3.47.0 force and selection](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/commands/precache.dart#L156-L196), [3.47.0 clear-all implementation](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/cache.dart#L710-L730).
- The group map is release-specific. 3.7.0's universal SDK uses only `sky_engine`, a host-named web ZIP with a CanvasKit fallback, and `FlutterMacOS.framework.zip`; 3.47.0 adds `flutter_gpu`, uses `flutter-web-sdk.zip`, and uses `framework.zip` for macOS desktop. A static modern filename allowlist would misread older SDKs. The framework checkout's `flutter_cache.dart` and `bin/internal/*.version` identify archive URLs and revisions for that release, but they do not give extracted-file hashes. [3.7.0 SDK and web](https://github.com/flutter/flutter/blob/3.7.0/packages/flutter_tools/lib/src/flutter_cache.dart#L160-L279), [3.7.0 macOS archive list](https://github.com/flutter/flutter/blob/3.7.0/packages/flutter_tools/lib/src/flutter_cache.dart#L854-L865), [3.47.0 SDK and web](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/flutter_cache.dart#L166-L287), [3.47.0 macOS archive list](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/flutter_cache.dart#L885-L900).

### Content validation and restoration

- Flutter validates a download's `x-goog-hash` MD5 **when that header is present**, against the downloaded ZIP bytes. That is a transfer check, not an expected digest for each extracted file. Flutter's `engine_stamp.json` contains build time, Git revision/date, and a build content hash; it is not a cache file manifest. Flutter removes downloaded archives after a successful update. [3.47.0 transfer check](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/cache.dart#L1350-L1410), [3.47.0 engine stamp parser](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/version.dart#L1373-L1414), [3.47.0 archive cleanup](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/cache.dart#L1452-L1476).
- `precache` can select platform groups, but it calls the same freshness checks and will say “Already up-to-date” when a file's bytes are corrupt while stamps and directories survive. `--force` redownloads after clearing all stamps and updates the checkout in place. Its archive updater extracts into a destination and explicitly notes that unzipping does not remove all stale files. Therefore Wren cannot simply run `precache` on a live SDK as a full validator or atomic repair; it would need its own staging and a version-aware account of which files each overlapping archive owns. [3.47.0 precache behavior](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/commands/precache.dart#L156-L197), [3.47.0 cache check](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/cache.dart#L930-L1039), [3.47.0 archive extraction](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/cache.dart#L1247-L1338).
- Some named `precache` artifacts are outside Wren's release-private SDK: Android Maven dependencies are cached by Gradle, and Flutter explicitly returns `false` for that group's freshness because it lets Gradle decide. Wren should define its repair scope as files inside its managed SDK/cache, unless it intentionally takes ownership of external Gradle state. [3.7.0 Android Maven artifact](https://github.com/flutter/flutter/blob/3.7.0/packages/flutter_tools/lib/src/flutter_cache.dart#L394-L476), [3.47.0 Android Maven artifact](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/flutter_cache.dart#L415-L488).

## Targeted check

I reproduced the exact engine-group freshness predicate from the two sampled `cache.dart` implementations in a temporary Linux tree with `engine/linux-x64`, `linux-x64-profile`, `linux-x64-release`, and a matching `linux-sdk.stamp`. The predicate returned `true` with an interior binary present, after replacing its bytes, and after deleting that binary: `{before: true, after_corruption: true, after_interior_deletion: true}`. This demonstrates the result of Flutter's source predicate for those states; it does not claim that a full Flutter binary was executed. [3.7.0 engine predicate](https://github.com/flutter/flutter/blob/3.7.0/packages/flutter_tools/lib/src/cache.dart#L843-L888), [3.47.0 engine predicate](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/cache.dart#L1014-L1042).

## Decision needed before implementation

The map should ask the human to settle the guarantee for a **first-seen optional group** fetched through a direct SDK path. Two viable boundaries are:

1. Keep complete content validation: Wren may fetch only that already-present group's source archive or a trustworthy version-specific file manifest during its first repair, even when the local group is sound; if unavailable, report “unverified” or repair failure rather than “healthy.” Generate and retain a digest manifest then, and use it for later offline checks. Define how to handle absent/corrupt stamps and fully erased groups.
2. Keep the no-download healthy path: Wren validates contents only for groups whose trusted manifest it recorded earlier. First-seen editor-fetched groups can receive structural/stamp checks but must be reported as **not fully verified**, or require a separate explicit deep-validation operation. This weakens the current full-`repair` promise.

Either way, implement a version-aware archive/footprint inventory for the supported release families, and stage replacements outside the live SDK before publishing under the existing external-use rule. Archive-specific postprocessing (for example, web SDK changes, nested macOS framework extraction, and removed file names) must be reflected in that inventory. Do not claim every supported Flutter release is covered merely from these two samples. [3.7.0 cache processing](https://github.com/flutter/flutter/blob/3.7.0/packages/flutter_tools/lib/src/cache.dart#L843-L968), [3.47.0 cache processing](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/cache.dart#L1014-L1081), [3.47.0 archive postprocessing](https://github.com/flutter/flutter/blob/3.47.0/packages/flutter_tools/lib/src/cache.dart#L1200-L1338).
