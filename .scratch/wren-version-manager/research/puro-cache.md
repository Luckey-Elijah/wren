# Puro installation and cache techniques

Source scope: Puro's public README and Dart source on its `master` branch, inspected 2026-10-26. This records Puro behavior and Wren design implications; it does not choose Wren's architecture.

## Findings

1. **Parallel checkout and engine fetch.** Puro starts an engine precache task, then clones/checks out Flutter, and only awaits that task after checkout. It obtains the engine commit before checkout from `bin/internal/engine.version` at the target Flutter commit, first from its shared Git repository and then from a Git-hosted HTTP file. If that version cannot be found, it skips precaching. Puro skips this optimization for fork installs. [Create environment, lines 153–199 and 259–317](https://github.com/pingbird/puro/blob/master/puro/lib/src/env/create.dart#L153-L317)

2. **Shared framework Git history.** Puro keeps a shared Flutter repository and gives each environment its own working tree. It fetches/clones into the shared repository when needed, initializes the environment repository, points `.git/objects/info/alternates` to the shared repository's object store, then fetches and checks out the requested commit locally. This is Git object sharing, not a single shared working tree. The shared object repository must remain while environment repositories reference it. [Shared clone path, lines 322–475](https://github.com/pingbird/puro/blob/master/puro/lib/src/env/create.dart#L322-L475); [Git alternates documentation](https://git-scm.com/docs/gitrepository-layout#Documentation/gitrepository-layout.txt-objectsinfoalternates)

3. **Shared engine cache.** Puro keys its shared Flutter cache by **engine commit hash**, distinct from Flutter release version. It downloads the platform's engine archive from Flutter's storage endpoint, unzips it into that commit's shared cache, and checks the cached Dart executable with `--version` before reusing it. A failed check deletes the cache. On macOS arm64, a 404 can trigger an x64 archive fallback for older releases. [Engine download, lines 165–251](https://github.com/pingbird/puro/blob/master/puro/lib/src/env/engine.dart#L165-L251); [Cache locations in configuration](https://github.com/pingbird/puro/blob/master/puro/lib/src/config.dart#L297-L309)

4. **Per-environment cache links.** Puro links individual shared cache entries into each environment's `flutter/bin/cache`, leaving version-check metadata local. It migrates existing local cache entries into the shared cache when possible. Puro's source says older versions linked the entire cache directory; the individual-entry approach avoids sharing files in its blacklist. Windows link creation may require elevation when Developer Mode is off. [Cache sync, lines 270–366](https://github.com/pingbird/puro/blob/master/puro/lib/src/env/engine.dart#L270-L366); [Windows link handling](https://github.com/pingbird/puro/blob/master/puro/lib/src/file_lock.dart#L240-L304)

5. **Locks and cleanup.** Puro locks an environment's update file while creating it, and its file-lock helper supports process-level shared/exclusive locks. Its garbage collector discovers engine commits referenced by installed environments, keeps a configurable number of unused shared caches and Flutter-tool snapshots, and deletes leftover ZIPs. [Environment update lock](https://github.com/pingbird/puro/blob/master/puro/lib/src/env/create.dart#L246-L317); [Lock helper](https://github.com/pingbird/puro/blob/master/puro/lib/src/file_lock.dart#L16-L79); [Garbage collector](https://github.com/pingbird/puro/blob/master/puro/lib/src/env/gc.dart#L8-L121)

## Implications and open checks for Wren

- Version-based installs can still use a shared object repository and engine-commit cache. Puro's named, independently upgradeable environments are an additional concept Wren has not requested. [Puro README](https://github.com/pingbird/puro#quick-start)
- Sharing engine cache entries requires a deliberate boundary between immutable shared artifacts and per-install mutable stamps/configuration; Puro's blacklist and migration logic are evidence of that boundary. [Cache sync](https://github.com/pingbird/puro/blob/master/puro/lib/src/env/engine.dart#L270-L366)
- **Inference from the inspected code:** the engine archive is written to a shared path during an environment-specific update lock. The cited download function does not itself acquire a shared-cache lock or stage extraction under a temporary directory. Wren should explicitly decide how two installs requesting the same engine commit coordinate and how partial extraction is recovered. [Create lock](https://github.com/pingbird/puro/blob/master/puro/lib/src/env/create.dart#L246-L317); [Engine download](https://github.com/pingbird/puro/blob/master/puro/lib/src/env/engine.dart#L165-L251)
- Windows symlink permissions and the older macOS arm64 release fallback are platform design inputs if Wren supports those targets. [Link helper](https://github.com/pingbird/puro/blob/master/puro/lib/src/file_lock.dart#L240-L304); [Engine fallback](https://github.com/pingbird/puro/blob/master/puro/lib/src/env/engine.dart#L210-L228)
